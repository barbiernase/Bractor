Der Kreislauf

Ein Klick stößt an — der Fortschritt streamt zurück

Training ist dasselbe Muster wie die bestehende Inferenz: ein out-of-process Python-Worker abonniert ein Event, reagiert, emittiert Commands. Nichts Neues am Transport — nur langlaufend, mit Fortschritt.

Der Zuschnitt

Drei fokussierte Aggregate

ImagePair und die Suche bleiben unverändert. Es kommen kleine, event-sourcete Aggregate dazu — je ein Ordner unter Domain/, wie ImagePair selbst.

Der Schnitt

C# erzeugt, Python nutzt — über ein Manifest

Genau die Aufteilung „Erzeugung in C#, Training in Python". Events tragen Pfade, keine Blobs — wie die Bildpfade heute. Der Datensatz ist im Log reproduzierbar; das Manifest ist nur eine Datei-Projektion davon.

▸ datasets/{id}/v1/manifest.json C# schreibt
// eingefroren, immutable — die Trainings-Wahrheit
{
  "datensatzId": "a3f…", "version": 1,
  "klassen": ["KeineAnomalie","Questionable","Anomalie"],
  "samples": [
    { "imagePairId":"…",
      "dc0Pfad":"…_DC0.png",
      "dc2Pfad":"…_DC2.png",
      "label":2, "split":"train" },
    …
  ]
}

Warum event-sourced

Reproduzierbarkeit ist geschenkt

Der eingefrorene Datensatz ist ein unveränderlicher Input; der Trainingslauf hält Datensatz-Version, Hyperparameter und Seed fest. Woraus ein Modell gelernt hat, steht lückenlos im Log.
